# 三位成员个人总支付 UC 分析

项目统一使用成员 **A、B、C**。主流程只分析个人总支付，UC候选为RW和LLT，基准为朴素预测及三期移动平均。

| --- | --- | --- | ---: |
| A | `raw_data/A_个人总支付_自然周.csv` | `个人总支付_元` | 88,167.33 |

A已换用新确认的真实CSV，旧A误用的115,040.44元序列已弃用，112个周金额均已修正。A的退款合计11,220.62元、净支付合计76,946.71元，逐周满足总支付减退款等于净支付；建模目标仍为总支付。逐周变更见`output/A成员数据修正逐周核对.csv`。

三份data中的Excel均为`UC数据`工作表，只含周期起始日和个人总支付_元，日期采用Excel数值日期及yyyy-mm-dd格式。共同区间为2024-09-02至2026-10-25，共112个完整自然周，周起始日截至2026-10-19。未插值、缩尾或额外删除大额支付。

B沿用净消费清洗和退款回冲原日口径，共同区间以外52.00元与224.28元仍在原始文件；C保留原总支付及校园卡代理支付、大额事件和原外币折算，首尾不完整周期不并入模型。三人前置清洗口径不完全相同，跨人比较需保留这些区别。

## 目录和报告

- `raw_data/`：按A、B、C命名的原始来源，仅本机保留。
- `data/`：三份规范化周度建模输入。
- `output/A/`、`output/B/`、`output/C/`：各人完整UC结果、图表、参数和结论。
- `output/A_B_C成员周消费_UC与基准预测报告.docx`：预测、诊断、性能、累计金额、A数据修正和C历史复现报告。
- `output/UC分析流程简述.md`：总体sequence图及四种方法流程图，模型用蓝紫橙绿、公共模块统一灰色，在支持Mermaid的阅读器中查看。
- `output/季节周期4测试/`：修正数据后重跑的RW4、LLT4实验，与主流程分别保存。
- `output/流程代码/`：分析、报告和独立核验程序。

## 运行与评价

MATLAB运行根目录`run_all_uc`。需要Econometrics Toolbox、Statistics and Machine Learning Toolbox及ECOTOOL。可先addpath工具箱，或设置`ECOTOOL_PATH`；程序也会检查Windows用户常规安装目录。

前108周训练至2026-09-27，后4周测试覆盖2026-09-28至10-25。以78周为初始历史扩展验证30个下一周预测。只有一个UC通过残差3、6阶检验时优先选择它，否则按滚动MAE、RMSE排序；测试误差不反馈选模。测试数据此前已观察，本轮是历史重算。

`prepare_report_results(projectRoot)`补齐四模型同原点预测和报告图表；`run_season4_test`另跑4周季节周期实验。`verify_results.py`、`verify_report.py`和`verify_season4_test.py`独立重算结果，`summarize_season4_test.py`生成季节实验结论。

Word重建：`python output/流程代码/build_uc_docx.py --template 参考报告.docx`。参考文件不随公开仓库分发。

## 历史复现与发布

`output/新旧结果对比说明.md`及`C新旧数值逐项核对.csv`核对C的原自然周结果。C数据未变，主要结果一致；旧稳定性日志60条索引异常与本轮不同，差异保留。C的复现不证明A数据正确。无本地整理前备份时主流程跳过重新执行旧基线核对，保留已发布证据。
