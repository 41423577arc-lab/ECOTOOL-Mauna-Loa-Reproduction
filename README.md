# 个人总支付 UC 分析数据

后续分析目标仅为个人总支付。原有代码、常规支付分析及旧分析结果已从项目清除，并保存在项目目录外的整理前备份中。当前重新引入的流程只分析三人的总支付。

## 目录与格式

- `raw_data/`：四份原始文件原样保留。
- `data/`：三人的 UC 输入文件，文件名与各自原始 Excel 完全一致。
- `output/`：三人的新 UC 结果、原流程适配代码及与旧 yyl 结果的对照。
- `run_all_uc.m`：在 MATLAB 中调用 `run_all_uc`，完整运行三人分析及新旧比较。需要 Econometrics Toolbox、Statistics and Machine Learning Toolbox 及原 ECOTOOL。
- 每份文件只有 `UC数据` 一个工作表，两列依次为 `周期起始日`、`个人总支付_元`。日期为 Excel 日期，金额为数值，单位为人民币元；无合计行、无常规支付列。

三份数据均按日期升序排列，采用周一至周日的自然周，共同区间为 2024-09-02 至 2026-10-25，即周起始日 2024-09-02 至 2026-10-19，共 112 个连续完整周。未插值、未缩尾、未额外剔除大额事件，未预设训练/测试划分。

## 边界及源数据限制

- 三人共同区间由 tg、yyl 原有完整周序列确定。cyx 的 2024-08-26 起始周只有账期内 2024-09-01 的记录，净支付 52.00 元；2026-10-26 起始周净支付 224.28 元，超出三人共同区间。本次均未放入 data，其记录仍在 raw_data，未按比例分摊或补造。
- yyl 原文件“05_不完整周期”里的首尾记录沿用源文件决定，不并入 UC 周序列；tg 没有逐笔底表，无法重建边界周。
- raw_data 中的 `C_个人总支付_自然周(1).csv` 与 tg Excel 的 112 个日期、金额完全一致，不作为第四人重复提取。
- cyx 保留源文件的净消费口径（退款回冲原支付日，原表已排除转账、储值等）；yyl 沿用其总支付口径（包含校园卡充值代理支付及原表认定的大额事件，并保留原表的外币折算）。未将各人的前置清洗规则强行统一，跨人比较时需考虑这些口径差异。
- 已核对 112 个周起始日唯一且间隔 7 天，金额均为有效非负数、精确至分，并重新打开导出的 Excel 逐行核对。
- 日期采用 Excel 数值日期及 `yyyy-mm-dd` 显示格式，避免 MATLAB 对 ISO 日期单元格的兼容性误读；日期和金额的含义不变。

## UC 运行口径

沿用旧自然周六步流程：数据准备、序列检验、RW/LLT 估计、残差诊断、训练期滚动验证、先锁定预测再评价保留测试期。前 108 周训练，初始 78 周并滚动验证 30 周；最后 4 周覆盖 2026-09-28 至 2026-10-25。基准为朴素和三期移动平均，仅分析总支付。新旧比较说明保存在 `output/新旧结果对比说明.md`。

新 yyl 应直接对照备份中的自然周总支付结果；旧月度、连续七天及整月日分摊结果用于结论参照，不能与不同区间的误差或四周合计直接要求数值相同。

## 分析报告和流程说明

- `output/三位成员周消费_UC与基准预测报告.docx`：含逐人预测曲线、残差诊断、四模型性能、累计金额及 yyl 新旧核对。
- `output/UC分析流程简述.md`：总体 sequence 时序图及 RW、LLT、朴素、三期移动平均流程图。模型模块分别用蓝、紫、橙、绿，公共模块统一灰色；在支持 Mermaid 的 Markdown 阅读器中查看。
- `output/报告四模型性能汇总.csv` 等三个“报告四模型”CSV：报告补充展示的数值依据。`output/流程代码/prepare_report_results.m` 生成这些表及报告图表，不改变原有 UC 选择。
- `output/流程代码/build_uc_docx.py`：使用原参考 DOCX 的组件生成 Word 报告，使用当前三份数据，未套用参考文件的人员身份或 ARIMA 结论。

目录已从 `output（2）` 改名为 `output`。旧整理前压缩包仍保留在项目目录外；历史运行日志中的原目录名称保留为当时的执行记录。

## 仓库发布与复现

公开仓库包含周度聚合输入、分析结果、图表和报告。`raw_data/` 的逐笔账单、本机运行日志及临时文件由 `.gitignore` 排除，仍在本机保留。

运行新分析前，在 MATLAB 中添加 ECOTOOL 工具箱路径，或设置 `ECOTOOL_PATH` 环境变量；程序也会检查 Windows 用户的常规工具箱安装目录。没有整理前本地备份时，`run_all_uc` 会完成三人分析并跳过重新执行旧基线核对，既有核对证据仍保存在 `output` 中。

`prepare_report_results(projectRoot)` 补齐报告四模型比较表及图表。报告作者可使用 `python output/流程代码/build_uc_docx.py --template 参考报告.docx` 重新生成 Word；参考文档不随公开仓库分发。`verify_results.py` 和 `verify_report.py` 可核对已保存的结果，后者可通过 `--template` 额外核对参考版式。
